## 🎯 核心功能方法

### 1. `_refresh_profile_list()` - 刷新方案列表

**功能**: 从ProfileManager获取所有方案名称，更新下拉框

**特点**:
- 自动保留当前选中项
- 第一项始终是 "-- 选择方案 --"
- 按保存顺序显示

**调用时机**:
- 程序启动时
- 保存新方案后
- 删除方案后

### 2. `_get_current_widget_config()` - 获取当前配置

**功能**: 从表格中选中的比赛行提取完整配置

**返回**:
```python
(config_dict, error_message)
# 成功: (config_dict, None)
# 失败: (None, "错误信息")
```

**验证**:
- 检查是否有选中行
- 检查该行是否有配置widget

### 3. `on_save_profile()` - 保存方案

**流程**:
1. 获取当前比赛的配置
2. 弹出对话框输入方案名称（默认: 方案_MMdd_HHmm）
3. 检查名称是否已存在，如存在则询问是否覆盖
4. 调用ProfileManager保存
5. 刷新方案列表
6. 自动选中新保存的方案

**用户交互**:
```
┌──────────────────────────┐
│     保存方案              │
├──────────────────────────┤
│ 请输入方案名称:           │
│ [方案_0417_1430      ]   │
│                          │
│       [确定]  [取消]      │
└──────────────────────────┘
```

### 4. `on_load_profile()` - 加载方案

**流程**:
1. 检查是否选择了方案
2. 获取当前选中的比赛
3. 从ProfileManager加载方案配置
4. 将配置应用到当前比赛的widget
5. 显示成功提示

**应用范围**:
- ✅ 进球规则（全场目标、上下半场阈值）
- ✅ 时间节点提醒（有进球时间、无进球时间）
- ✅ 水位监控（亚盘主队/客队、大小球大/小）
- ✅ 盘口变化（亚盘盘口、大小球盘口）

**注意**: 不覆盖比赛特定信息（match_id, home_team, away_team）

### 5. `on_delete_profile()` - 删除方案

**流程**:
1. 检查是否选择了方案
2. 弹出确认对话框（警告不可恢复）
3. 调用ProfileManager删除
4. 刷新方案列表
5. 显示成功提示

**安全防护**:
- 二次确认对话框
- 明确的警告信息
- 日志记录

## 🔍 使用示例

### 场景1: 保存常用配置

**操作步骤**:
1. 筛选出一批比赛
2. 勾选第一场比赛
3. 在下方配置卡片中设置：
   - 上半场进球: ✓ 启用, 阈值: 2球
   - 下半场进球: ✓ 启用, 阈值: 1球
   - 上半场无进球: ✓ 启用, 30分钟
   - 下半场无进球: ✓ 启用, 70分钟
4. 点击工具栏的 "💾 保存" 按钮
5. 输入方案名称: "激进型监控"
6. 点击确定

**结果**: 
- 方案保存到 `monitor_profiles.json`
- 下拉列表中显示 "激进型监控"
- 日志显示: `[方案] 已保存方案: 激进型监控`

### 场景2: 批量应用方案

**操作步骤**:
1. 筛选出新的比赛
2. 勾选第一场比赛
3. 在下拉列表中选择 "激进型监控"
4. 点击 "📥 加载" 按钮
5. 该比赛的配置自动更新为方案中的设置
6. 重复步骤2-5，应用到其他比赛

**优势**: 
- 无需逐个配置
- 保证一致性
- 节省时间

### 场景3: 管理多个方案

**典型方案**:
```
1. 激进型监控
   - 上半场进球: 1球
   - 下半场进球: 1球
   - 上半场无进球: 25分钟
   - 下半场无进球: 65分钟

2. 保守型监控
   - 上半场进球: 3球
   - 下半场进球: 2球
   - 下半场无进球: 75分钟

3. 只关注无进球
   - 上半场无进球: 30分钟
   - 下半场无进球: 70分钟

4. 高比分监控
   - 全场目标: 5球
   - 上半场进球: 2球
   - 下半场进球: 3球
```

**操作**:
- 随时切换方案
- 删除不再需要的方案
- 根据比赛类型选择合适的方案

## ⚠️ 注意事项

### 1. 配置范围
方案只保存监控规则，不包含：
- ❌ match_id（比赛ID）
- ❌ home_team（主队名称）
- ❌ away_team（客队名称）

这些是比赛特定的信息，每个比赛都不同。

### 2. 方案命名
- 建议使用有意义的名称
- 避免特殊字符
- 可以使用中文或英文
- 推荐格式: `类型_描述`

### 3. 覆盖保护
- 保存时如果方案名已存在，会弹出确认对话框
- 删除时需要二次确认
- 防止误操作

### 4. 数据持久化
- 方案保存在 `monitor_profiles.json`
- 程序重启后自动加载
- 可以手动备份该文件
