# v16 修复冷却记录清理类型错误

## 🐛 问题描述

**错误信息：**
```
[缓存清理] 清理失败: unsupported operand type(s) for -: 'float' and 'datetime.datetime'
```

**问题分析：**
- 在清理过期告警冷却记录时，尝试用 `float` 减去 `datetime.datetime` 对象
- `time.time()` 返回浮点数（时间戳）
- `alert_cooldown` 中存储的是 `datetime` 对象
- 两者不能直接相减，导致类型错误

---

## 🔍 根本原因

### 问题代码（修复前）

**位置：** `monitor_engine.py` 第1022-1027行

```python
# v16新增: 清理过期的告警冷却记录（超过5分钟的记录）
now = time.time()  # ← 返回 float（时间戳）
expired_cooldowns = []
for key, last_time in self.alert_cooldown.items():
    if now - last_time > 300:  # ← ❌ float - datetime = TypeError!
        expired_cooldowns.append(key)
```

### 数据来源分析

**`alert_cooldown` 的存储方式：**

在 `_try_trigger` 方法中（第2048、2061行）：
```python
def _try_trigger(self, match_id, alert_type, message):
    key = (match_id, alert_type)
    now = datetime.now()  # ← datetime 对象
    
    # ... 其他逻辑 ...
    
    self.alert_cooldown[key] = now  # ← 存储 datetime 对象
```

**清理时的读取方式：**
```python
now = time.time()  # ← float 时间戳
for key, last_time in self.alert_cooldown.items():
    if now - last_time > 300:  # ← float - datetime = ❌
```

**类型不匹配：**
- 存储：`datetime` 对象
- 清理：`float` 时间戳
- 运算：`float - datetime` → **TypeError!**

---

## 🔧 修复方案

### 修复后的代码

**位置：** `monitor_engine.py` 第1022-1039行

```python
# v16新增: 清理过期的告警冷却记录（超过5分钟的记录）
now = time.time()
expired_cooldowns = []
for key, last_time in self.alert_cooldown.items():
    try:
        # v16修复: 处理不同类型的last_time
        if isinstance(last_time, datetime):
            # 如果是datetime对象，转换为时间戳
            last_timestamp = last_time.timestamp()
        else:
            # 否则假设是时间戳
            last_timestamp = float(last_time)
        
        if now - last_timestamp > 300:  # 5分钟 = 300秒
            expired_cooldowns.append(key)
    except (TypeError, ValueError):
        # 如果转换失败，删除该记录
        expired_cooldowns.append(key)

for key in expired_cooldowns:
    del self.alert_cooldown[key]

if expired_cooldowns:
    self.log_signal.emit(f"[冷却清理] 已清理{len(expired_cooldowns)}条过期冷却记录")
```

## 📋 修复逻辑详解

### 1. 类型检测

```python
if isinstance(last_time, datetime):
    # 如果是datetime对象，转换为时间戳
    last_timestamp = last_time.timestamp()
else:
    # 否则假设是时间戳
    last_timestamp = float(last_time)
```

**处理策略：**
- 检查 `last_time` 的类型
- 如果是 `datetime` 对象，调用 `.timestamp()` 方法转换为时间戳
- 否则，假设已经是时间戳，转换为 `float`

---

### 2. 统一使用浮点数运算

```python
if now - last_timestamp > 300:  # float - float = ✅
    expired_cooldowns.append(key)
```

**运算逻辑：**
- `now`: `float` 时间戳（来自 `time.time()`）
- `last_timestamp`: `float` 时间戳（转换后）
- `now - last_timestamp`: `float - float` = ✅ 成功

---

### 3. 异常处理

```python
except (TypeError, ValueError):
    # 如果转换失败，删除该记录
    expired_cooldowns.append(key)
```

**处理策略：**
- 捕获 `TypeError`：类型转换失败
- 捕获 `ValueError`：值转换失败
- 如果转换失败，直接删除该记录（可能是损坏的数据）

## 🎉 总结

**问题根源：**
- `alert_cooldown` 中存储的是 `datetime` 对象
- 清理时使用 `time.time()` 返回的 `float` 进行减法运算
- 类型不匹配导致 `TypeError`

**修复方案：**
1. 检测 `last_time` 的类型
2. 如果是 `datetime` 对象，转换为时间戳
3. 统一使用 `float` 进行减法运算
4. 添加异常处理，删除损坏数据

**修复效果：**
- ✅ 不再出现类型错误
- ✅ 兼容多种数据类型
- ✅ 自动清理损坏数据
- ✅ 向后兼容（支持旧的时间戳格式）

**防御性编程原则：**
- 永远不要假设数据类型是固定的
- 在使用前进行类型检查和转换
- 使用 `try-except` 捕获意外异常
- 对于无法处理的数据，采取保守策略（删除）
