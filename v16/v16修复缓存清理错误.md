# v16 修复缓存清理错误

## 🐛 问题描述

**错误信息：**
```
[缓存清理]清理失败:unsupported operand type(s)for and 'datetime.datetime'
```

**问题分析：**
- 在清理过期比赛结束状态时，尝试对 `datetime` 对象进行减法运算
- 但 `end_detected_time` 可能是 `None` 或其他非 `datetime` 类型
- 导致 `(datetime.now() - end_time)` 运算失败

---

## 🔍 根本原因

### 问题代码（修复前）

**位置：** `monitor_engine.py` 第1045-1052行

```python
# v16新增: 清理过期的比赛结束状态（超过30分钟）
expired_end_states = []
for match_id, state in self.match_end_states.items():
    end_time = state.get('end_detected_time')
    if end_time:  # ❌ 只检查了是否为真值，没有检查类型
        elapsed = (datetime.now() - end_time).total_seconds()
        if elapsed > 1800:  # 30分钟 = 1800秒
            expired_end_states.append(match_id)
```

### 问题场景

**场景1：`end_time` 为 `None`**
```python
state = {'end_detected_time': None, ...}
end_time = None
if end_time:  # False，不会执行
    ...
```
这种情况不会出错，因为 `if end_time` 会返回 `False`。

**场景2：`end_time` 不是 `datetime` 对象**
```python
state = {'end_detected_time': '2024-01-01', ...}  # 字符串
end_time = '2024-01-01'
if end_time:  # True，会执行
    elapsed = (datetime.now() - end_time).total_seconds()  # ❌ TypeError!
```

**场景3：`end_time` 是其他类型**
```python
state = {'end_detected_time': 1234567890, ...}  # 整数时间戳
end_time = 1234567890
if end_time:  # True，会执行
    elapsed = (datetime.now() - end_time).total_seconds()  # ❌ TypeError!
```

---

## 🔧 修复方案

### 修复后的代码

**位置：** `monitor_engine.py` 第1045-1068行

```python
# v16新增: 清理过期的比赛结束状态（超过30分钟）
expired_end_states = []
for match_id, state in self.match_end_states.items():
    end_time = state.get('end_detected_time')
    # v16修复: 确保end_time是datetime对象且不为None
    if end_time and isinstance(end_time, datetime):
        try:
            elapsed = (datetime.now() - end_time).total_seconds()
            if elapsed > 1800:  # 30分钟 = 1800秒
                expired_end_states.append(match_id)
        except Exception:
            # 如果计算失败，也删除该记录
            expired_end_states.append(match_id)
    elif end_time is None:
        # end_time为None，说明比赛还未真正结束，不删除
        pass
    else:
        # end_time不是datetime对象，删除无效记录
        expired_end_states.append(match_id)

for match_id in expired_end_states:
    del self.match_end_states[match_id]

if expired_end_states:
    self.log_signal.emit(f"[结束状态清理] 已清理{len(expired_end_states)}个过期比赛结束状态")
```

## 📋 修复逻辑详解

### 1. 类型检查

```python
if end_time and isinstance(end_time, datetime):
```

**检查内容：**
- `end_time` 不为 `None`、`False`、`0` 等假值
- `end_time` 是 `datetime` 类型

**效果：**
- 只有同时满足两个条件，才会执行时间计算
- 避免了类型错误

---

### 2. 异常处理

```python
try:
    elapsed = (datetime.now() - end_time).total_seconds()
    if elapsed > 1800:
        expired_end_states.append(match_id)
except Exception:
    # 如果计算失败，也删除该记录
    expired_end_states.append(match_id)
```

**处理策略：**
- 如果时间计算成功，检查是否超过30分钟
- 如果计算失败（任何异常），直接删除该记录
- **理由：** 无法计算的记录很可能是损坏的数据，应该清理

---

### 3. 处理 `None` 值

```python
elif end_time is None:
    # end_time为None，说明比赛还未真正结束，不删除
    pass
```

**处理逻辑：**
- `end_time` 为 `None` 表示比赛还未检测到结束
- 不应该删除这类记录
- 等待后续检测到结束时再设置时间

---

### 4. 处理无效类型

```python
else:
    # end_time不是datetime对象，删除无效记录
    expired_end_states.append(match_id)
```

**处理逻辑：**
- `end_time` 存在但不是 `datetime` 类型
- 这是无效数据，应该删除
- 例如：字符串、整数、列表等

## 🎉 总结

**问题根源：**
- 未对 `end_detected_time` 进行类型检查
- 直接进行 `datetime` 减法运算，导致类型错误

**修复方案：**
1. 添加 `isinstance(end_time, datetime)` 类型检查
2. 使用 `try-except` 捕获异常
3. 分别处理 `None` 值和无效类型
4. 确保只有有效的 `datetime` 对象才参与计算

**修复效果：**
- ✅ 不再出现类型错误
- ✅ 正确处理各种边界情况
- ✅ 自动清理无效和损坏的数据
- ✅ 保留有效的未结束比赛记录

**防御性编程原则：**
- 永远不要假设数据类型是正确的
- 在使用前进行类型检查
- 使用 `try-except` 捕获意外异常
- 对于无效数据，采取保守策略（删除或忽略）
