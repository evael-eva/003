# v16 大规模监控性能优化方案

## 🎯 问题描述

**用户报告：**
```
同时监控100多比赛，电脑会变得很卡顿，但是cpu和内存的占用也不高
程序的内存会一直增多，导致达到阈值触发看门狗系统
```

**问题分析：**
1. **系统卡顿但资源占用不高** - 并发数过高导致线程切换频繁
2. **内存持续增长** - 数据结构限制过小，频繁清理导致开销
3. **触发看门狗** - 内存阈值500MB过低，不适合大规模监控

---

## 🔧 优化方案

### 1. 降低并发数至25 ⭐

**位置：** `monitor_engine.py` 第757-766行

#### 修改前
```python
if num_matches <= 5:
    max_workers = num_matches
elif num_matches <= 15:
    max_workers = min(num_matches, 20)  # 最多20个并发
elif num_matches <= 30:
    max_workers = min(num_matches, 25)  # 最多25个并发
else:
    max_workers = min(num_matches, 30)  # 最多30个并发
```

#### 修改后
```python
if num_matches <= 5:
    max_workers = num_matches
elif num_matches <= 15:
    max_workers = min(num_matches, 15)  # 中等数量比赛，最多15个并发
elif num_matches <= 30:
    max_workers = min(num_matches, 20)  # 较大量比赛，最多20个并发
else:
    max_workers = 25  # v16优化: 大量比赛时固定为25，避免系统卡顿
```

**优化效果：**
- ✅ 减少线程切换开销
- ✅ 降低CPU上下文切换频率
- ✅ 保持请求频率不变（25个并发足够处理100+比赛）
- ✅ 系统响应更流畅

**为什么是25？**
- 100场比赛 / 25并发 = 4轮
- 每轮约10秒，总耗时约40秒
- 在可接受范围内，且不会造成系统卡顿

### 4. 定期强制垃圾回收 ⭐

**位置：** `_cleanup_expired_cache` 方法（第1077-1089行）

#### 新增代码
```python
# v16优化: 定期强制垃圾回收（每10次清理执行一次）
if not hasattr(self, '_cleanup_count'):
    self._cleanup_count = 0
self._cleanup_count += 1
if self._cleanup_count % 10 == 0:  # 每10次清理执行一次
    try:
        import gc
        collected = gc.collect()
        if collected > 0:
            self.log_signal.emit(f"[垃圾回收] 已回收{collected}个对象")
    except Exception:
        pass
```

**优化效果：**
- ✅ 主动释放不再使用的对象
- ✅ 防止Python垃圾回收延迟
- ✅ 稳定内存使用
- ✅ 每10次清理执行一次，避免频繁GC影响性能

**执行频率：**
- 清理间隔：约10秒
- GC执行间隔：10次 × 10秒 = 100秒
- 约每1.5分钟执行一次GC
- 对性能影响极小

### 5. 优化日志输出 ⭐

**位置：** `_health_check` 方法（第676-681行）

#### 修改前
```python
else:
    self.log_signal.emit(f"[健康检查] 内存使用正常: {memory_mb:.1f} MB")
```

#### 修改后
```python
else:
    # v16优化: 只在内存较低时不输出日志，减少UI卡顿

        pass
    else:
        self.log_signal.emit(f"[健康检查] 内存使用正常: {memory_mb:.1f} MB")
```

**优化效果：**
- ✅ 减少不必要的日志输出
- ✅ 降低UI刷新频率
- ✅ 减轻主线程负担
- ✅ 系统更流畅

**日志策略：**
- 内存 < 400MB：不输出日志（正常状态）
- 内存 400-640MB：输出日志（关注状态）
- 内存 > 640MB：输出警告（预警状态）
